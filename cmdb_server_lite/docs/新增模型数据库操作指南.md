# CMDB 新增模型数据库操作指南

## 概述

本文档说明在 **cmdb_server_lite** 项目中新增自定义模型时，需要创建的数据库表、数据及依赖关系。

**技术架构**：
- **Web 框架**：Flask 2.3.3
- **数据库层**：SQLAlchemy 2.0.35+（仅作为连接池和原生 SQL 执行器，禁用 ORM Model）
- **方言处理**：sqlglot 19.8.0（多数据库 SQL 方言转换）
- **支持数据库**：SQLite（开发默认）、PostgreSQL（生产推荐）、MySQL（可选）
- **表结构规范**：与原项目（蓝鲸 CMDB MongoDB 版本）保持一致的字段命名与业务语义

**相关文件**：
- 配置：[settings.py](file:///workspace/cmdb_server_lite/app/config/settings.py)
- 引擎：[engine.py](file:///workspace/cmdb_server_lite/app/db/engine.py)
- 迁移：[migrate.py](file:///workspace/cmdb_server_lite/app/migrate/migrate.py)
- 服务：[instance_service.py](file:///workspace/cmdb_server_lite/app/service/instance_service.py)
- 启动入口：[run.py](file:///workspace/cmdb_server_lite/run.py)

---

## 案例场景

以 **"应用系统"** 和 **"应用子系统"** 为例，演示从无到有的完整新增流程：

- 一个 **应用系统** 可以关联 **N 个应用子系统**
- 关联关系：1:N（一对多）

## 一、数据库表体系与新增流程

### 1.1 核心表体系

```
┌────────────────────────────────────────────────────────────┐
│              cmdb_server_lite 核心表体系                     │
├────────────────────────────────────────────────────────────┤
│                                                            │
│   cc_ObjClassification  —— 分类定义表                        │
│        ↓                                                    │
│   cc_ObjDes            —— 模型定义表（bk_obj_id 主键）        │
│        ↓                                                    │
│   cc_PropertyGroup    —— 属性分组表（每张模型都有默认/基础）   │
│        ↓                                                    │
│   cc_ObjAttDes        —— 属性定义表（字段描述）               │
│        ↓                                                    │
│   cc_AsstDes          —— 关联类型表（指向/属于/包含）          │
│        ↓                                                    │
│   cc_ObjAsst          —— 模型关联表（模型与模型之间的关系）    │
│        ↓                                                    │
│   cc_ObjectBase_0_pub_{obj_id} —— 各模型的实例数据分表        │
│        ↓                                                    │
│   cc_InstAsst_0_pub   —— 实例关联关系表（所有模型共用）       │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

### 1.2 新增模型标准步骤

```
步骤1: 定义模型 → cc_ObjDes
步骤2: 定义属性分组 → cc_PropertyGroup
步骤3: 定义属性 → cc_ObjAttDes
步骤4: [可选] 定义关联类型 → cc_AsstDes
步骤5: [可选] 定义模型关联 → cc_ObjAsst
步骤6: 创建实例分表 → cc_ObjectBase_0_pub_{obj_id}
步骤7: [可选] 导入示例实例数据
步骤8: [可选] 导入实例关联数据
```

### 2.4 cc_ObjAttDes（属性定义表）

**作用**：定义模型的字段结构（前端据此生成表单、表格、搜索条件等）

**表结构**（来自 [migrate.py#L374-L403](file:///workspace/cmdb_server_lite/app/migrate/migrate.py#L374-L403)）：

```sql
CREATE TABLE IF NOT EXISTS cc_ObjAttDes (
    _id VARCHAR,
    id INTEGER,
    bk_obj_id VARCHAR NOT NULL,                          -- 所属模型ID
    bk_property_id VARCHAR NOT NULL,                     -- 属性唯一ID（字段名）
    bk_property_name VARCHAR NOT NULL,                   -- 属性显示名
    bk_property_type VARCHAR NOT NULL,                   -- 属性类型
    bk_property_group VARCHAR DEFAULT 'default',         -- 所属分组ID
    isrequired BOOLEAN DEFAULT false,                    -- 是否必填
    bk_ispassword BOOLEAN DEFAULT false,                 -- 是否密码字段
    bk_ishidden BOOLEAN DEFAULT false,                   -- 是否隐藏
    isreadonly BOOLEAN DEFAULT false,                    -- 是否只读
    editable BOOLEAN DEFAULT true,                        -- 是否可编辑
    bk_isapi BOOLEAN DEFAULT false,                      -- 是否API内部字段（过滤显示）
    bk_issystem BOOLEAN DEFAULT false,                   -- 是否系统字段
    ispre BOOLEAN DEFAULT false,                         -- 是否预置
    ismultiple BOOLEAN DEFAULT false,                    -- 是否多选（enummulti 专用）
    bk_property_index INTEGER DEFAULT 0,                 -- 属性排序
    option TEXT,                                         -- 选项配置（JSON字符串）
    placeholder VARCHAR,                                  -- 占位符
    unit VARCHAR,                                         -- 单位
    creator VARCHAR DEFAULT 'admin',
    modifier VARCHAR DEFAULT 'admin',
    create_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_time TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    bk_supplier_account VARCHAR DEFAULT '0',
    PRIMARY KEY (bk_obj_id, bk_property_id)
)
```
#### 1. `bk_isapi` — API 内部字段  
  
**含义**：该字段仅供后端 API 内部使用，**不应出现在前端表单中**。  
  
**前端使用逻辑**（[form.vue#L246-L250](file:///workspace/bk-cmdb/src/ui/src/components/ui/form/form.vue#L246-L250)）：  
  
```javascript  
checkEditable(property) {  
  if (this.type === 'create') {  
    return !property.bk_isapi  // 创建时：isapi=true → 不显示  
  }  
  return property.editable && !property.bk_isapi  // 编辑时：editable=true 且 isapi=false → 才显示  
}  
```  
  
**典型场景**：  
- `id`（数据ID）、`bk_inst_id`（实例ID）→ `bk_isapi=true`，前端表单中**完全不显示**  
- `bk_obj_id`（模型ID）→ `bk_isapi=true`，前端表单中不显示  
  
---  
  
#### 2. `bk_issystem` — 系统字段  
  
**含义**：该字段由系统自动管理，**前端不应让用户修改其选项配置**（如枚举选项）。  
  
**前端使用逻辑**：  
- `bk_issystem=true` 的字段在**模型字段管理页面**中不能被用户编辑/删除字段定义  
- 后端在返回分类对象查询时**会删除此字段**（[object.go#L1311](file:///workspace/bk-cmdb/src/scene_server/topo_server/logics/model/object.go#L1311)）：`delete(attrInfo, "bk_issystem")` — 不向前端暴露  
  
**典型场景**：  
- `bk_inst_name`、`bk_obj_id` 等系统字段 → `bk_issystem=true`  
- 系统字段**仍然可以在实例表单中显示和编辑**（如 `bk_inst_name` 可编辑），只是不能在模型管理中修改其定义  
  
---  
  
#### 3. `ispre` — 预置字段  
  
**含义**：该字段是模型预置的（内置的），**用户不能删除或修改字段定义**。  
  
**前端使用逻辑**（[index.vue#L643-L651](file:///workspace/bk-cmdb/src/ui/src/components/model-manage/field-group/index.vue#L643-L651)）：  
  
```javascript  
isFieldEditable(item, checkIspre = true) {  
  if ((checkIspre && item.ispre) || this.isReadOnly || !this.updateAuth) {  
    return false  // ispre=true → 不能编辑字段定义  
  }  
  ...  
}  
```  
  
- `ispre=true` 的字段**不能删除**（[index.vue#L170](file:///workspace/bk-cmdb/src/ui/src/components/model-manage/field-group/index.vue#L170)：`v-if="!property.ispre"` 控制删除按钮显示）  
- 预置的枚举/列表字段不能修改选项（[tools.js#L705-L706](file:///workspace/bk-cmdb/src/ui/src/utils/tools.js#L705-L706)）：  
  
```javascript  
const { bk_property_type: type, ispre } = property  
return !ispre && fields.includes(type)  // ispre=true → 不能修改选项  
```  
  
**典型场景**：  
- 所有系统属性（`id`、`bk_inst_id`、`bk_inst_name`、`bk_obj_id`）→ `ispre=true`  
- 业务内置属性（如 `name`、`status`）→ `ispre=true`  
  
---  
  
### 组合条件关系总结  
  
| 场景 | 判断条件 | 说明 |  
|------|----------|------|  
| **是否在表单中显示** | `!bk_isapi` | isapi=true → 表单不显示该字段 |  
| **创建时是否可编辑** | `!bk_isapi` | 创建时只看 isapi，忽略 editable |  
| **编辑时是否可编辑** | `editable && !bk_isapi` | 编辑时需要 editable=true 且 isapi=false |  
| **编辑时是否禁用** | `!editable \|\| isreadonly` | 不可编辑或只读 → 禁用 |  
| **模型管理能否编辑字段定义** | `!ispre` | ispre=true → 不能编辑字段定义 |  
| **模型管理能否删除字段** | `!ispre` | ispre=true → 不能删除字段 |  
| **能否修改枚举选项** | `!ispre` | ispre=true → 不能修改选项 |  
| **是否在表格列中显示** | `!bk_ishidden && !bk_isapi` | 隐藏或API字段不出现在表格中 |  
| **bk_issystem 的作用** | 后端过滤不返回 | 控制字段定义是否暴露给前端模型管理 |  
  
#### 核心区别  
  
```  
bk_isapi  → 控制"字段是否在实例表单/表格中出现"（粒度最粗，直接不显示）  
bk_ishidden → 控制"字段是否在表格列中显示"（隐藏但仍可在详情/表单中看到）  
editable   → 控制"字段值是否可编辑"（显示但只读 vs 可输入）  
isreadonly → 控制"已创建的实例该字段是否只读"（编辑模式下的禁用）  
bk_issystem → 控制"字段定义是否对前端模型管理暴露"（后端层面控制）  
ispre      → 控制"字段定义是否可被用户修改/删除"（模型管理层面的保护）  
```

#### option 字段格式规范（来自 [migrate.py#L7-L13, L505-L557](file:///workspace/cmdb_server_lite/app/migrate/migrate.py#L7-L13)）

`option` 字段存储为 **JSON 序列化字符串**，后端 API 会自动反序列化。

| 属性类型 | option 存储格式示例 |
|---------|---------------------|
| enum（单选枚举） | `[{"id":"running","name":"运行中","type":"text","is_default":true}]` |
| enummulti（多选枚举） | `[{"id":"HTTP","name":"HTTP","type":"text","is_default":true}]` |
| list（列表） | `["北京","上海","广州"]` |
| int（整数范围） | `{"min":0,"max":100}` |
| float（浮点范围） | `{"min":0.0,"max":100.5}` |
| table（表格） | `{"header":[...],"default":[...]}` |
| 其他类型 | `null`（不存储） |

**注意**：
- 单选枚举（enum）的 `is_default` 只能有 1 个为 true
- 多选枚举（enummulti）必须同时设置 `ismultiple = true`，且 `is_default` 可以多个
- 简单数组会通过 `convert_enum_option()` 自动转换为原项目标准格式

## 四、数据库操作最佳实践

### 4.1 新增实例（来自 [instance_service.py](file:///workspace/cmdb_server_lite/app/service/instance_service.py)）

```python
from app.db.executor import query_one, execute
from app.utils.tools import generate_id
import json

def create_instance(model_id, data):
    """创建实例：统一使用 bk_inst_id 作为标准实例ID"""
    instance_id = generate_id()
    data['id'] = instance_id
    data['_id'] = instance_id
    data['bk_inst_id'] = instance_id    # 必设
    data['bk_obj_id'] = model_id        # 必设
    data.setdefault('bk_supplier_account', '0')

    # 处理枚举/列表等复合字段为 JSON 字符串
    attributes = get_model_attributes(model_id)
    for attr in attributes:
        prop_id = attr['bk_property_id']
        prop_type = attr['bk_property_type']
        if prop_id in data and prop_type in ['list', 'enum', 'enummulti', 'object', 'array']:
            if isinstance(data[prop_id], (list, dict)):
                data[prop_id] = json.dumps(data[prop_id], ensure_ascii=False)

    columns = ', '.join(data.keys())
    placeholders = ', '.join([f':{k}' for k in data.keys()])
    table_name = f'cc_ObjectBase_0_pub_{model_id}'
    sql = f'INSERT INTO "{table_name}" ({columns}) VALUES ({placeholders})'
    execute(sql, data)
    return instance_id
```

## 五、字段与 ID 规范总结

### 5.1 必须使用 bk_inst_id 作为实例唯一标识

| 位置 | 字段 | 类型 | 说明 |
|------|------|------|------|
| 实例表 | `bk_inst_id` | INTEGER | 蓝鲸标准实例ID，**前后端唯一标识** |
| 实例表 | `id` | INTEGER | 数据库主键，**前端不直接使用** |
| 关联表 | `bk_inst_id` / `bk_asst_inst_id` | INTEGER | 源/目标实例的 bk_inst_id |
| API 路径 | `/api/v1/models/{model_id}/instances/{inst_id}` | - | `inst_id` 使用 `bk_inst_id` |
| 关联组件 | 点击行后传参 | - | 使用 `row.bk_inst_id` |

### 5.2 实例表必含字段

```
id              INTEGER PRIMARY KEY      数据库内部主键
bk_inst_id      INTEGER NOT NULL         蓝鲸标准实例ID
bk_inst_name    VARCHAR NOT NULL         实例名称（展示用）
bk_obj_id       VARCHAR NOT NULL         所属模型ID
bk_supplier_account  VARCHAR DEFAULT '0' 供应商账号
create_time     TIMESTAMP                创建时间
last_time       TIMESTAMP                修改时间
bk_operate_time TIMESTAMP                操作时间
```

### 5.3 前端新增/编辑表单字段筛选

前端需要从 cc_ObjAttDes 中过滤以下字段后，才作为表单字段：

| 条件 | 含义 |
|------|------|
| `bk_property_id NOT IN ('id', 'bk_inst_id', 'bk_obj_id', ...)` | 排除系统字段 |
| `bk_isapi = false` | 排除 API 内部字段（如数据ID、实例ID、模型ID） |
| `bk_ishidden = false` | 排除隐藏字段 |

### 5.4 属性分组显示顺序

- 先按 `cc_PropertyGroup.bk_group_index` 排序分组
- 再按 `cc_ObjAttDes.bk_property_index` 排序分组内属性
- `default` 分组一般排在最前（包含系统属性），`base` 分组用于业务属性

## 六、支持的数据库与方言差异

| 数据库 | 连接池实现 | 自增主键 | 时间戳类型 | JSON 字段类型 |
|--------|-----------|---------|-----------|--------------|
| **SQLite**（开发） | StaticPool | `INTEGER PRIMARY KEY AUTOINCREMENT` | `TIMESTAMP`（存储为文本） | `TEXT` |
| **PostgreSQL**（生产） | QueuePool（size=5, overflow=10, recycle=3600s） | `SERIAL` / `IDENTITY` | `TIMESTAMP` | `JSONB`（本项目暂用 TEXT 以兼容 SQLite） |
| **MySQL**（可选） | QueuePool | `INTEGER PRIMARY KEY AUTO_INCREMENT` | `DATETIME` | `JSON` / `TEXT` |

切换数据库只需修改 `.env` 或 `config_by_env` 中的 `DATABASE_TYPE`，数据迁移脚本通过 `sqlglot` 做方言兼容，无需改动 SQL。

### 8.4 前端逻辑效果

**批量更新表单**（[form-multiple.vue](file:///workspace/cmdb_ui_lite/src/components/ui/form/form-multiple.vue)）：

1. 通过 API `/find/objectunique/object/{model_id}` 获取模型的所有唯一约束
2. 将约束中涉及的所有属性加入 `uniquePropertyIds` 数组
3. 在 `isPropertyEditable()` 方法中判断：如果属性在 `uniquePropertyIds` 中，返回 `false`
4. 用户**无法在批量更新表单中选择或编辑这些属性**

**多条唯一约束处理**：

- 场景：`bk_switch` 模型有两条约束
  - 约束1：`bk_inst_name`（实例名称）单独唯一
  - 约束2：`bk_inst_name + bk_management_ip`（实例名称+管理IP）组合唯一
- 处理结果：`uniquePropertyIds = ['bk_inst_name', 'bk_inst_name', 'bk_management_ip']`
- 效果：`bk_inst_name` 和 `bk_management_ip` **都会被隐藏**（只要属性参与任一条唯一约束，就不允许批量更新）

### 8.5 后端实现逻辑

**创建实例校验**（[instance_service.py](file:///workspace/cmdb_server_lite/app/service/instance_service.py)）：

```python
def check_unique(self, model_id, data, exclude_instance_id=None):
    """校验唯一约束"""
    unique_constraints = InstanceService.get_object_unique_constraints(model_id)
    for constraint in unique_constraints:
        keys = constraint.get('keys', [])
        query_parts = []
        query_values = {}
        
        for key in keys:
            property_id = key.get('bk_property_id')
            if property_id in data:
                query_parts.append(f'"{property_id}" = :{property_id}')
                query_values[property_id] = data[property_id]
        
        if query_parts:
            where_clause = ' AND '.join(query_parts)
            if exclude_instance_id:
                where_clause += f' AND bk_inst_id != :exclude_id'
                query_values['exclude_id'] = exclude_instance_id
            
            sql = f'SELECT COUNT(*) FROM "cc_ObjectBase_0_pub_{model_id}" WHERE {where_clause}'
            count = execute(sql, query_values)
            if count > 0:
                raise ValidationException('唯一约束冲突')
```

def batch_update_instances(self, model_id, ids, data):
    """批量更新实例"""
    # 检查是否更新了唯一字段
    unique_constraints = InstanceService.get_object_unique_constraints(model_id)
    unique_property_ids = set()
    for constraint in unique_constraints:
        keys = constraint.get('keys', [])
        for key in keys:
            property_id = key.get('bk_property_id')
            if property_id:
                unique_property_ids.add(property_id)
    
    for field_name in data.keys():
        if field_name != 'last_time' and field_name in unique_property_ids:
